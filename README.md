# Bein Store

متجر عربي RTL مبني باستخدام Next.js 15 وTypeScript وSupabase، مع كتالوج، صفحات تفاصيل المنتج، سلة مشتريات محفوظة في المتصفح، إتمام طلب، واتساب، ولوحة إدارة للمنتجات والطلبات.

## الوظائف الموجودة

- كتالوج للمنتجات النشطة التي لها سعر معتمد فقط، مع بحث وتصفية حسب الماركة.
- صفحة تفاصيل لكل منتج، وسلة محفوظة في المتصفح، وتعديل الكميات والحذف.
- إتمام الطلب والتحقق من بيانات العميل على الخادم. قاعدة البيانات تعيد قراءة الأسعار الحالية وتحسب الإجمالي بنفسها؛ لا تثق في أسعار المتصفح.
- تسجيل الطلب وبنود الطلب، وتحديث المخزون فقط للمنتجات التي لها سجل مخزون صريح.
- دخول الإدارة عبر Supabase Auth مع التحقق من جدول `admin_roles`، وإدارة المنتجات والأسعار والصور عبر روابط، ومراجعة الطلبات وتحديث حالتها.
- واجهة عربية متجاوبة واتصال واتساب قابل للإعداد من متغيرات البيئة. لا توجد بيانات منتجات أو أسعار أو مخزون تجريبية.

## التشغيل المحلي

المتطلبات: Node.js 20.9 أو أحدث وnpm.

1. انسخ `.env.example` إلى `.env.local`.
2. قيمة رابط Supabase موجودة بالفعل. ضع المفتاح العام (Publishable key أو anon key) في `NEXT_PUBLIC_SUPABASE_ANON_KEY`. تجده من إعدادات API للمشروع.
3. (اختياري قبل الإطلاق) أضف بيانات التواصل المؤكدة إلى `NEXT_PUBLIC_STORE_PHONE` و`NEXT_PUBLIC_STORE_WHATSAPP` و`NEXT_PUBLIC_STORE_ADDRESS` داخل `.env.local`. اتركها فارغة إلى أن يتم تأكيدها؛ لن يعرض المتجر أرقامًا أو عناوين افتراضية.
4. شغّل: `npm install` ثم `npm run dev` وافتح `http://localhost:3000`.
5. اختبر الإنتاج باستخدام `npm run build` ثم `npm start`.

## حالة التنفيذ قبل الإطلاق

- أضيفت تصنيفات الكتالوج ومسودات المنتجات في قاعدة البيانات المتصلة؛ لم تُنشر المنتجات ولم تُضف أسعار أو مخزون.
- لا يوجد حتى الآن حساب مسؤول مضاف إلى `admin_roles`، ولا توجد استضافة عامة أو نطاق مربوط.
- محاولة تثبيت حزم npm في بيئة التجهيز انتهت بمهلة زمنية؛ لذلك لم يُثبت نجاح `npm run build` بعد.

## إعداد مسؤول المتجر

1. من Supabase Dashboard افتح Authentication وأنشئ مستخدمًا من صفحة Users.
2. انسخ UUID الخاص بالمستخدم.
3. نفّذ في SQL Editor، مع استبدال UUID بالقيمة الحقيقية:

```sql
insert into public.admin_roles (user_id, role, is_active)
values ('PUT-AUTH-USER-UUID-HERE', 'admin', true);
```

لا تضف مفتاح `service_role` أو أي مفتاح سري إلى متغير يبدأ بـ `NEXT_PUBLIC_`. صلاحيات الإدارة محمية بسياسات RLS.

## قاعدة البيانات والأمان

- مشروع Supabase المتصل: `rtmricyjkygcgqfbufjk`، في منطقة Frankfurt.
- الجداول الأساسية وسياسات RLS موجودة بالفعل في المشروع المتصل. ملفات migrations محفوظة كمرجع ضمن `supabase/migrations/`.
- لا يوجد دفع إلكتروني مفعّل؛ الطلب يسجل كطلب جديد ثم يفتح رسالة واتساب لتأكيد التفاصيل. رسوم الشحن تظل صفرًا مبدئيًا وتظهر على أنها تُحدد لاحقًا، ولا يتم تحصيلها تلقائيًا.
- تم تجهيز 6 تصنيفات و14 سجل منتج كمسودات استنادًا إلى موديلات/أسماء ذُكرت سابقًا. كل المنتجات مخفية، والأسعار فارغة، ولا توجد صور أو سجلات مخزون مضافة. راجع الموديلات والتوفر، ثم أدخل السعر والصورة والكمية الفعلية من لوحة الإدارة قبل نشر أي منتج.
- أُضيفت هجرة `202610140005_harden_public_checkout_rpc.sql` لتقييد RPC الخاص بالطلب على دور `anon` فقط، وإفراغ `search_path` لتقليل خطر object shadowing. تحذير Supabase المتبقي بشأن `SECURITY DEFINER` قابل للتنفيذ بواسطة `anon` متوقع في تصميم checkout للزوار، ويحتاج مراجعة إضافية/تحديد معدل الطلبات قبل الإطلاق العام.
- يجب اختبار `npm install`, `npm run lint`, و`npm run build` في بيئة التشغيل قبل النشر. محاولة التثبيت الحالية فشلت لأن بيئة التجهيز لا تستطيع الوصول إلى `registry.npmjs.org`؛ لذلك لم يتم تأكيد نجاح البناء. لم يتم إعداد استضافة عامة أو نطاق مخصص.
